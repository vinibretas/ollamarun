    Contributing¶

    This is a personal project, but the internals are documented for anyone reading along. CLAUDE.md and AGENTS.md (mirror copies) describe the module layout, the conventions (Python 3.10, rich, argparse in main()) and where to change what. There is no contribution process; issues are welcome, but the roadmap is whatever I am learning next — currently the web UI.

    Run the tests with python3 test_ollamarun.py. The suite doubles as the compatibility contract for both API surfaces — it round-trips the official openai SDK and exercises a real ollamarun serve process against a stub backend — and --live adds a pass against a real Ollama server.

    Where to change what¶

    • New tool: add defs/tools/NAME.json (description, JSON schema, safety flags, optional requires/aliases, handler name), the handler function and its HANDLERS entry in tools.py, and a row in the README tool table. Registration is data-driven — default_registry() picks the file up automatically, and read_only/always_safe feed approval_decision().
    • New slash command: one cmd_NAME(repl, argument) function in repl.py, wired into COMMAND_INFO/COMMAND_HANDLERS; complete the build_parser() epilog and the README command table when it is notable.
    • New config key: add it to DEFAULT_CONFIG in constants.py and to the README's selected-keys list; user config merges over the defaults.
    • New inspection output (--list-style): build it into a cli_* function and route through emit() (emit.py), never a hand-rolled table.
    • New example client: examples/ holds the runnable reference clients (the official-SDK one and the native-agent one); they double as the test_examples regression against the fake stack and are covered by the pyflakes gate, so keep them clean, runnable and mirrored in the README's Example clients section.
    • New interactive prompt/hook: extend the Ui protocol and ConsoleUi in ui.py, then implement it in TuiUi (tui.py) — nothing below the repl.py layer may know which front end is running. Set interactive on an implementation that can actually ask; the approval gate reads it.
    • New runtime event: add the type to events.py, emit it from runtime.py, and teach the consumers (Repl's event printer, HeadlessRenderer, the future HTTP layer) — the event stream is the contract between the runtime and every front end.
    • New /v1 endpoint: register it in openai_api.build_router() (OpenAI-compatible surface) or the right native group — agent_api.add_agent_routes() (turns/sessions/fits) or add_artifact_routes() (shared files/artifacts), and keep transport concerns in server.py (body caps, SSE framing, error envelopes); handlers raise ApiError for structured errors and return a Response or StreamResponse. The agent layer reuses turns.py's manager plus a headless Repl, never the OpenAI mapping.
    • New model-facing text: tool wording in defs/tools/*.json, prompt text in defs/prompts/; never hardcode it in Python.
    • Streaming/rendering UX: renderer.py (the TUI consumes the same frames through StreamSink), and ui.py's StatusSnapshot/format_status() when it shows up in the status bar.
    • New docs page: place it under its surface — docs/cli/, docs/api/, docs/tui/, docs/web-ui/ — or the global docs/getting-started// docs/config/; register it in mkdocs.yml's nav and assemble it from existing sources with --8<-- snippet includes (README.md, a marked AGENTS.md section, plans/) rather than copying text. Command collections stay on one reference page. Verify with mkdocs build --strict.

    Testing notes¶

    The suite is two files: test_ollamarun.py (the shared harness, CLI, renderer and tool tests) and test_ollamarun_serve.py (everything runtime/turns/serve/agent/artifact/fit); the canonical command python3 test_ollamarun.py imports and runs both. Tests are table-driven: some sections are a CASES-style list of (name, input, predicate) tuples run through a small harness, others are a test_*() -> int function that prints PASS/FAIL lines and returns a failure count, mirroring the pattern documented in ~/bin/AGENTS.md (test_modelbenchmark.py is the canonical example there); all test_* functions are summed in the if __name__ == "__main__": block at the bottom. The math-rendering tests (MATH_CASES) are the largest block and the most likely place a change to the layout engine (mathrender.py) will need new coverage. OllamaClient is tested against a fake requests.Session (_FakeSession/_FakeResponse) rather than a real HTTP mock library; REPL/CLI-level tests use _FakeClient (a lighter double with the handful of methods those layers actually call) instead. Console output assertions that capture the shared console singleton (with orun.console.capture() as cap:) should go through the _plain() helper before substring-matching, since rich's automatic number/keyword highlighting can split a literal substring across ANSI color codes. The Phase 1/1b runtime tests (test_runtime_events, test_headless_renderer, test_session_store_lock, test_session_store_cross_process_lock, test_ui_interactive, test_tool_cancellation, test_cancellation_coverage, test_file_mention_inlining, test_tool_support_warning, test_quiet_tools_live, test_approval_event_contract, test_python310_syntax, test_turn_result_mapping) cover the AgentRuntime event stream, the terminal-free turn path, the in-process/cross-process store locks, turn cancellation (including the ssh/chem/tts/trash coverage), @file inlining, the approval event contract and the 3.10 syntax guard. The audit guards (test_runtime_event_contract, test_approval_runtime_contract, test_unattended_turn_denial, test_cancel_reaches_production_tools, test_quiet_tools_real_turn, test_session_store_process_gate, test_session_store_same_session_writers, test_session_store_without_fcntl, test_cancellation_destructive_guard) pin the event vocabulary/serialization and terminal-event contract, the approval order with its interrupt/stopped paths, the cancel token actually reaching a production turn's tool, the store flock gating another process, and the destructive-tool refusal after a stop. The Phase 2 tests (test_turn_event_envelope, test_turn_manager_lifecycle, test_turn_manager_synthesized_terminal, test_turn_buffer_truncation, test_turn_expired, test_turn_manager_session_busy, test_turn_manager_max_active, test_turn_manager_cancel, test_turn_subscriber_overflow, test_turn_manager_shutdown, test_turn_manager_context, test_turn_manager_headless_turn) cover envelopes, lifecycle, replay/gap/truncation, session exclusivity, the active cap, cancellation, overflow and shutdown. The Phase 3 serve tests (test_openai_mapping, test_embeddings_api, test_serve_http, test_serve_disconnect, test_serve_sockets, test_serve_cache_concurrency, test_serve_cli, test_openai_sdk) pin request validation and message/tool mapping (strict types, exact error envelopes), the embeddings schema and gates, n > 1 and parallel_tool_calls behavior, the live HTTP surface over a fake backend (models, non-stream and SSE chat, tool calls, the vision gate, body and image caps), client-disconnect cancellation with stream isolation, the wired request timeout (stalled body 408, streams outliving it), single-flight caches, the serve parser, config defaults and main() dispatch, and the official OpenAI SDK round-trip including negative and mid-stream-failure paths (a required gate: it fails when the package is missing and prints the SDK version it exercised). The Phase 6 hardening tests (test_serve_config_matrix, test_chunked_bodies, test_input_limits, test_native_parameters, test_workspace_jail, test_artifact_root_containment, test_serve_model_gate, test_serve_agent_switch, test_serve_shutdown, test_serve_unload_on_exit) pin the validated serve matrix and its transport wiring, chunked decoding, the aggregate resolved-input budget, native option validation, the workspace jail, artifact-root containment, the model allowlist, the serve_agent route groups, the shutdown order and the tracked unload. test_serve_process spawns the real ollamarun serve binary against a stub upstream (banner-discovered address, a completion, a SIGTERM mid-stream drain, a clean exit, the tracked unload), test_turn_mode_isolation pins the model-turn-vs-agent-turn contrast, test_examples runs both reference clients against the fake stack, and test_pyflakes_clean is the lint gate (it covers ollamarun_lib/, the examples/ clients, the entry script and both test files). python3 test_ollamarun.py --live additionally runs a real-backend smoke test (models, completion with usage, streaming, embeddings — OLLAMARUN_TEST_EMBED_MODEL overrides the first embedding-capable pick — and one full agent turn; tool round-trip with OLLAMARUN_TEST_MODEL set). The Phase 4 agent tests (test_agent_turn_lifecycle, test_agent_turn_controls, test_agent_approvals, test_agent_approval_edge, test_agent_policy_mode, test_agent_disconnect_policy, test_agent_turn_timeout, test_agent_sessions_api, test_agent_turn_validation, test_agent_turn_expiry, test_agent_context_warning) pin the full-turn path (202/status/events/session persistence), session-busy 409 with the active id and the global-cap 429, approval parking with run/remember/deny and duplicate rejection, approval timeout, cancellation and shutdown while waiting, policy-mode allow/deny, disconnect vs cancel_on_disconnect, the wall-clock turn timeout, the session CRUD routes, the turn-schema malformed matrix, 404/410 turn status and the headless context warning/compaction. The Phase 5 artifact tests (test_artifact_store, test_artifact_quota_and_ttl, test_tool_artifact_registration, test_artifact_events, test_artifact_session_persistence, test_artifact_content_parts, test_artifact_remote_fetch, test_artifact_upload_api, test_artifact_fetch_api, test_serve_approval_timeout_zero) pin the store (ids, hashes, immutability, traversal-shaped ids, sanitized names, concurrent quota reservations, TTL/reconciliation sweeps), tool publication (file tools' destinations, publish_artifact jailing and gating, note-not-failure), the artifact.created ordering and persistence, the shared content resolver (inlining, binary notes, 404s, remote-fetch rules against a local stub server) and the HTTP endpoints (201 refs, strict validation, 413/507, download headers, 404 and the no-store 503). The Phase 10 context-control tests (test_ctxfit_outcome, test_ctxfit_cancel_progress, test_fit_service, test_session_context_fields, test_fit_estimate_api, test_fit_job_api, test_turn_start_fit) pin the structured fit_context() outcome and its data-shaped failures, cancellation at estimate/probe checkpoints and progress stages, the fit service (lifecycle, caps, per-session exclusivity, TTL, apply hook, shutdown), the first-class num_ctx/gpu_layers fields (strict validation, unload parity, persistence), the estimate endpoint matrix and policy gates, the async job API (202 + warnings, status/progress, cancel, apply, 404/409/429) and the turn-start estimate (session.fit, result.fit, persistence, the no-change failure path). Fit tests inject the machine (MachineGpu) and read-only RAM probes, so they need no GPU.
