    Architecture¶

    ollamarun_lib/ is organized as pipeline stages, one module per stage; read a module's own docstring for what lives there before editing:

    1. constants.py — shared stdlib/rich/optional-dependency imports, VERSION, config/session/log paths, THEME, the shared console singleton, DEFAULT_CONFIG, the DEFAULT_SERVE_* transport/limit defaults, and the tool-panel colours (TOOL_COLORS/ TOOL_COLOR_PALETTE, tool_color() with its random per-run fallback, set_tool_colors() for the config tool_colors overrides). Every other module sits on top of this one.
    2. helpers.py — small helpers: ISO timestamps, id generation, bool/host/think coercion, --remote resolution (resolve_remote, remote_node, tailscale_map, tailscale_peer_state, is_local_host), disk-space probes (local_free_disk, ssh_free_disk — the ssh probes take a cancel token), run_cancellable()/CommandCancelled (the process-group-killing subprocess runner every tool shares), config load (load_config) and the response-timings policy (resolve_show_stats), logging setup, and the count formatters shared by both front ends (human_tokens/format_context for the ctx counter, human_chars, human_duration), serve_settings() (the one validated serve_* policy matrix: defaults, types, ranges and zero semantics, consumed by serve_main), model_allowed() (the serve_models tag-aware fnmatch allowlist) and ModelTracker (the models a serve process used, for unload-on-exit).
    3. mathrender.py — LaTeX → Unicode, combined in one module because the two halves call into each other: regex-level conversion for inline math (convert_math, latex_to_unicode) falls through to the 2D layout engine's render_inline_math for inline math, and the layout engine falls back to convert_math/latex_to_unicode for anything unsupported. The layout engine is a self-contained parser/box-layout system for display math ($$...$$, \[...\]): _tokenize_math → _MathParser → an AST of M* node classes (MFrac, MSqrt, MScript, MBigOp, MMatrix, MCases, MAligned, MBoxed, etc.) → _layout() builds a _Box (list-of-strings + width) recursively → _flatten() is the plain-text fallback path. render_display_math()/render_inline_math() are the public entry points; both must never raise — anything unsupported (unknown environment, over-wide, over-budget) falls through to pylatexenc. This module also has render_content()/render_thinking() (markdown + centered display math, used by the renderer and REPL). Changes here need care: the layout is hand-rolled string-grid arithmetic, not a real typesetting library.
    4. files.py — @file mentions: expand_file_mentions() inlines file contents into a prompt.
    5. images.py — encode_image/image_payload, base64 embedding with max_file_kb truncation.
    6. renderer.py — Renderer class drives a rich.Live view: incremental markdown re-render while tokens stream, the collapsible thinking panel (render_thinking, Ctrl+T expand/collapse in place; /thinking full prints the stored panel directly), and TpsEstimator (windowed()/average()/rate()) for the live footer: windowed rate, cumulative average, streamed tokens and a ctx counter that counts the round's chunks on top of the context_used/ context_total the REPL passes in, and the per-response ⏱ timings line whose visibility comes from resolve_show_stats() (on by default on a terminal, piped output only with --verbose, config show_stats: false as the off-switch). StreamSink is the seam the TUI uses: with a sink, stream() pushes the same frames to a widget instead of a rich.Live, so both front ends share one streaming loop (and stream(cancel=…) honors a CancelToken). Also has the chat-bubble helpers (user_message_box, small right-aligned box for a user turn; model_message_panel, full-width titled box for a model turn) and the tool panels -- tool_call_panel()/tool_result_panel(), both coloured by constants.tool_color() so every tool keeps one identity across the live view and the transcript (tool_result_panel also takes a note that lands in the title -- the speak tool's optiplex → g3, persisted on the tool message as tool_note) -- plus render_transcript() (replays a saved session the way it looked live, used by /show/--show). This is the piece that talks to the terminal frame-by-frame; changes to streaming UX go here. consume_chunk() is the shared per-chunk accumulator and HeadlessRenderer is the terminal-free presenter (it emits message.delta events instead of printing), used by the runtime's headless turns.
    7. client.py — OllamaClient wraps /api/chat, /api/generate, /api/embed, /api/ps, /api/pull, /api/create etc. over raw requests, streaming response bodies line-by-line (including pull progress events). build_chat_payload() assembles the request body from CLI args + session history.
    8. tools.py — the tool harness: ToolSpec/default_registry() (shell, python, files — read/write/list plus edit_file and the make_dir/move_file/copy_file/delete_file chores — web_search when ddgs is installed, fetch_url, search_sessions, list_models, system_status, context_status/session_info, tts-remote speak/list_voices, and the chemInventoryAPI lookup tools when that CLI is present), the allowlist policy (shell_safety, python_safety, approval_decision), the approval-rule engine (ToolRule, suggest_rules, rule_matches, dangerous_command), argument normalization, output truncation and execute_tool(). The tool declarations load from the definition files — one JSON per tool under defs/tools/ (ToolDefinition, load_tool_definitions(); HANDLERS maps the JSON's handler name onto the function, requires gates a tool on a capability, tool_aliases() is built from the aliases lists so invented names like search/curl resolve onto the real tools, and resolve_tool_alias() strips a call-id prefix (call_fetch_url) and retries on a miss; bad files warn and are skipped). ToolSpec keeps each definition's requires and aliases (REQUIREMENT_HINTS words them for the help pages). ToolHandlerResult(text, artifact_paths) is the optional structured handler return: execute_tool() registers regular files through ToolContext.artifacts (the turn-bound TurnArtifacts publisher the serve API injects) and attaches the refs to the ToolOutcome; plain strings still work for every handler that produces no files. ToolContext carries the runtime seams the REPL injects: client/store (list_models, system_status, search_sessions), ssh_target/ssh_user for remote probes, chem_inventory (the CLI path override), artifacts (the serve publisher), context_report/session_report (the plain dicts Repl.context_report()/session_report() assemble for the awareness tools) and workspace (the API path jail: when set, path arguments and the run_shell/run_python working directories resolve under it and resolved escapes including symlinks are refused; the CLI leaves it unset). The web half is self-contained: _HTMLTextExtractor/extract_html_text turn pages into readable text plus links, extract_pdf_text uses pypdf or pdftotext, format_fetch_response maps a response onto model-readable text (never the site's error page), run_web_search wraps ddgs. The speech half speaks through run_tts_say() (an older tts-remote without --json is retried without it) and turns the say --json plan into the shared title_note via speech_hosts(). The agent loop that calls into it lives in runtime.py (approve → execute → append a role: tool message → ask the model again), auto-speak lives in Repl.speak_text, and rendering of calls/results is renderer.py. ToolContext.cancel reaches every subprocess-backed tool (shell, python, the ssh probes, chemInventoryAPI, tts-remote, trash-put) through helpers.run_cancellable(), and ToolRunner abandons network tools (fetch_url, web_search) on cancel so the result is discarded instead of waited on.
    9. prompts.py — the prompt files: load_prompt() (override layer first, shipped default after, cached per process; missing/unreadable warns and reads as None), default_system_prompt() (composes system.md + system_tools.md when tools are on), title_prompt()/summarize_prompt() (both expand {{content}}) and render_prompt(). Defaults live in defs/prompts/.
    10. events.py — the runtime event vocabulary: RuntimeEvent plus the turn.*/message.*/tool.*/approval.* type constants, artifact.created and session.fit, and TERMINAL_EVENTS. A leaf module (no imports from the package) shared by renderer.py, runtime.py and the HTTP layer; envelopes, sequence numbers and replay are added on top of the same types, so nothing here depends on transport.
    11. session.py — Session (in-memory conversation model: messages, model, system prompt, options; artifacts accumulates the refs the conversation saw, add_artifacts() dedupes by id) and SessionStore (atomic read/write of the JSON files + index.json, list/search/export/delete; its index read-modify-write runs under a shared RLock plus an exclusive flock on <index>.lock (so a CLI saving while serve runs cannot lose entries) and its temp files are named per writer. export_markdown/export_json/export_html are the three export formats.
    12. emit.py — emit() plus the cli_list/cli_search/cli_show/ cli_export/cli_delete functions that implement the non-interactive inspection flags.
    13. ui.py — the front-end seam: Ui (the interactive hooks repl.py and interactive.py call: ask, confirm, editor, approval, notify, and interactive — whether the front end can actually ask), ConsoleUi (the inline implementation — the same rich prompts as always, notifications are a no-op; interactive follows console.is_terminal), the tool-approval choice list (approval_entries/approval_lines) and the numbered typed prompt _prompt_approval (moved here so the console prompt and the TUI modal are built from one list), and the status-bar model (StatusSnapshot, format_status(), spinner_frame()): plain data plus a pure formatter (context text via format_context, tps + tps_avg), unit-testable without a terminal.
    14. interactive.py — open_in_editor ($OLLAMA_EDITOR), pick_model/pick_session (fuzzy pickers; ui= routes the question to the TUI front end), model_context_length (reads context window from /api/show), and the missing-model flow: ensure_model() (free-space line + y/N pull prompt, --pull skip, picker on decline), pull_with_progress() and disk_free_line(). Model-list sorting lives here too: MODEL_SORT_KEYS/parse_model_sort (modified|name|size|parameters|context, plus aliases), model_parameter_count (parses details.parameter_size, MoE totals included), sort_models/model_table (shared by the picker and /model --list) and fetch_context_lengths/cached_context_length (one /api/show per uncached model, in parallel behind a status line, cached per host); pick_model takes sort=/on_sort= and its prompt accepts --sort KEY/-s KEY/sort KEY to re-order the table in place. Also the GPU-layer spec logic: model_block_count(), parse_gpu_layers_spec(), resolve_gpu_layers(), gpu_layers_label().
    15. ctxfit.py — the context fits behind /num-ctx --max-gpu and /num-ctx --max-cpu N: kv_bytes_per_token() (llama.cpp's KV formula applied to /api/show's GGUF metadata, per-layer head_count_kv arrays included), machine_state_for()/probe_machine_gpu() (free VRAM plus the ollama unit env) and machine_ram_for()/probe_machine_ram() (available DRAM from /proc/meminfo), locally or over one ssh probe each; estimate_max_gpu_ctx() (weights from /api/tags, llama.cpp's fit margin, resident models' /api/ps VRAM credited back, pinned /gpu-layers); estimate_max_cpu_ctx() (the budget is MemAvailable plus the resident model's own host RAM -- a reload returns it -- and the host footprint is the weights plus per-token KV of the layers llama.cpp's fit leaves on the CPU, max_cpu_overhead_mb reserved); the /api/ps-verified probe_max_gpu_ctx()/probe_max_cpu_ctx() that solve each next candidate from the measured affine footprint line instead of bisecting, plus ModelProfile/model_profile() (the parameters/quantization cross-check, per-layer KV geometry with sliding windows and MLA, ssm.*/shortconv recurrent state and the embedding/output/block weight split behind every estimate) and CtxCalibrationStore (bounded, host/model/placement-scoped measured samples that calibrate later estimates and seed probe search; stale/incompatible data falls back to the profile) (FitRequest/GpuFit/CpuFit/ProbeResult), the rich reports and max_gpu_context()/max_cpu_context(), which the REPL command and the CLI --num-ctx max-gpu / --num-ctx --max-cpu N flags both call. The probes themselves live in helpers.py (local_gpu_probe, ssh_gpu_probe, local_ram_probe, ssh_ram_probe, host_is_self).
    16. runtime.py — the agent turn runtime: AgentRuntime (the loop and tool execution that used to live in Repl._generate/ Repl._execute_tool_calls), TurnSettings, TurnHooks (the host seam: payload builder, presenter, approver, event sink, boundary drain), ApprovalRequest/ApprovalDecision, TurnResult, and the shared build_payload()/context_report()/session_report() helpers. It never prints and never touches a terminal; the CLI supplies a rich presenter and keeps thin wrappers with the old signatures, while HeadlessRenderer + an event sink drive it with no terminal at all. The runtime owns the tool-support capability check (once per model, after turn.started, warned as a turn.warning), and quiet_tools is read live so /render raw mid-turn takes effect. Tool artifacts: the runtime emits one artifact.created per ref between the approval decision and tool.result (which references the ids), stores the refs on the tool session message and accumulates them onto TurnResult.artifacts.
    17. turns.py — the turn manager: TurnEvent envelopes (turn id, 1-based seq, ISO timestamp, deterministic id), TurnManager (a worker thread per turn, one active turn per session, a global cap, per-turn buffers, replay with stream.gap, TTL retention swept on every entry point (subscribe() included), cancellation, begin_shutdown() (refuse new submissions before the ordered cancel/join), shutdown, and synthesized error terminals that carry the stable INTERNAL_ERROR_MESSAGE while the raw crash text goes to the --debug log and stays on the internal TurnResult), TurnHandle/Subscription/ TurnSnapshot, and the typed errors (SessionBusy/TooManyTurns/ UnknownTurn/TurnExpired) the HTTP layer maps to 409/429/404/410. It imports no front end: a host closure runs the runtime and returns a TurnResult; wait() joins a worker for tests and shutdown, and a subscriber that falls behind is closed, never stalling the turn.
    18. repl.py — SlashCompleter/completion_candidates (completion for /commands, session ids, models, @files, shared with the TUI input), the Repl class (the CLI adapter over runtime.AgentRuntime: _generate and _execute_tool_calls are thin wrappers that build the per-turn TurnHooks and render its events, _approve_tool_call is the policy + prompt approver, and the MessageQueue/CancelToken machinery is unchanged). headless + event_sink make the same object drivable with no terminal. _payload() is the one chat- request builder: it prepends the effective system prompt as a leading role: system message — Repl.effective_system() returns the session's text when set, the built-in default otherwise, None when disabled (empty string) — deliberately not stored in session.messages, so /system changes land on the next request and exports keep the history clean. Repl.context_length() is the one effective-window resolver behind the footer/status-bar ctx counter, /context and the 80%/85% warnings: a session num_ctx first, then the loaded runner's /api/ps context_length, then /api/show's model default; a show-only answer stays provisional until /api/ps reports the runner. model_show() is the run-long /api/show cache the length/block-count/awareness readers share, and context_report()/session_report() assemble the plain dicts the context_status/session_info tools format (window + usage, identity + settings + tool round). /system semantics live in _apply_system (clear/default → built-in, off → disabled, text → custom) plus _show_system, shared with /set system. Then the cmd_* functions. The numbered tool-approval prompt itself and the entry list it is built from (approval_entries/_prompt_approval, storing generalized ToolRules in the session) now live in ui.py, re-exported here so _prompt_approval keeps resolving from this module. Each slash command (/model//models, /set, /show, /load, /save, /pull, /num-ctx, /gpu-layers, /params, /tools, /tts, /think, /thinking, /system, /undo, /retry, /edit, /branch, /context, /summarize, /image, /render, /math, /pager, /tps, /copy, /export, /stats, /queue, ...) is a standalone cmd_NAME(repl, argument) function dispatched by name through COMMAND_HANDLERS; COMMAND_INFO is the authoritative description table (the REPL /help, the README's command table and the cli.py epilog all mirror it). Add a new slash command by adding one function here and wiring it into COMMAND_INFO/COMMAND_HANDLERS (and the hand-maintained build_parser() epilog in cli.py). /tools takes a tool name (or alias) as its first token for per-tool control — NAME on|off|help|call ARGS: _find_tool resolves aliases and falls back to tool_definitions() so an uninstalled tool still gets a page, _print_tool_help renders state/description/parameters/approval from the definition JSON, and _cmd_tools_call runs the tool through the normal approval gate without touching the conversation. completion_candidates/_tools_completion Tab-complete the whole command (subcommands, names and aliases, per-tool actions, policy modes, rule kinds) in both front ends. ps_table()/resolve_num_ctx() also live here since cmd_ps/ cmd_num_ctx are their only callers (resolve_num_ctx is reused by main() in cli.py for --num-ctx). ApprovalPicker and its runners are re-exported from ui.py for compatibility.
    19. tui.py — the optional Textual front end (--ui tui), deprecated: it will be rewritten as a pure ollamarun serve API client instead of reaching into the runtime in-process. Current code: the app (transcript pane / rule / status bar / always-on PromptInput), TuiStreamSink (the StreamSink that paints the streaming answer), TranscriptWriter (a file-like sink capturing everything printed through the shared console into the transcript), the modal screens (confirm, ask, and tool approval offering the same numbered choices as the console prompt) and TuiUi (the Ui implementation repl.py talks to). Turns and commands run in thread workers that marshal widget updates back with call_from_thread; run_tui() is the entry point. Textual is optional — cli.py's wants_tui() checks it and falls back to the inline REPL with a note.
    20. run.py — run_once() (non-REPL path, built on an already-constructed Repl; its --json branch runs the tool loop through AgentRuntime directly) and run_embed() (routes embedding-capable models to /api/embed instead of chat).
    21. server.py — the generic HTTP plumbing behind ollamarun serve: Router (method + {param} path patterns, with distinct 404/405), the Request/Response/StreamResponse model, HttpServer (a ThreadingHTTPServer wrapper with a body cap checked before the body is read — Content-Length and chunked alike, the chunked decoder enforcing the cumulative decoded cap before each chunk and rejecting ambiguous or malformed framing — socket timeouts, daemon handler threads and a bounded drain() over its tracked in-flight handlers) and SseWriter (one HTTP chunk per event, flushed; a : ping heartbeat from a companion thread; a failed write marks the stream broken exactly once and fires the response's on_disconnect). ApiError renders as the sanitized {"error": {...}} envelope; any other exception is a bare 500 and its traceback goes only to the --debug log. run_forever() serves on a worker thread with SIGINT/SIGTERM mapped to a clean shutdown(). It knows nothing about OpenAI or Ollama.
    22. artifacts.py — the artifact subsystem behind the serve API's files/artifacts endpoints and the file content parts: ArtifactStore (immutable snapshots behind opaque art_… ids; register() reserves quota in the index under the SessionStore lock pattern — RLock + flock — publishes with a temp file + os.replace, writes one authoritative manifest per artifact under meta/, and sweep()s TTL expiries, stale reservations and debris at startup and, rate-limited, on registration; every index/manifest path read back must resolve inside the store root) and ArtifactRef (the public record: id, media type, sanitized display filename, size, sha256, source, turn/session provenance, created_at and the relative url; TurnArtifacts is the turn-bound publisher tools receive through ToolContext.artifacts). The shared content layer lives here too: resolve_content_parts() maps text/image_url/file parts for both API surfaces (text inlining bounded by INLINE_TEXT_BYTES, TEXTUAL_MEDIA_TYPES as the deterministic text rule, binary parts described but never faked, missing ids a structured 404), charging every part/image/text byte to an optional InputBudget (InputLimits/input_limits, the aggregate serve_max_* caps: message/part counts, message and total text bytes, image counts and cumulative decoded image bytes), fetch_remote_media() is the one bounded http(s) fetch (redirects, timeouts, size cap) and require_vision() the one image capability check. It raises server.ApiError directly — it exists for the HTTP layer. Imports constants, helpers, server.
    23. fits.py — the context-fit jobs behind the native API's fit surface: FitService (a worker thread per job; queued → running → completed/failed/cancelled; per-session exclusivity, a global max_active_fits cap, cancel via the job's token, TTL sweeping of terminal jobs and an idempotent shutdown that cancels and joins) and FitJob/fit_body (the HTTP shape) plus FitBusy/TooManyFits/ FitsClosed. Jobs run one ctxfit.fit_context() and report progress through the request's on_progress; the optional session write is the API's on_success hook, so this module never touches the store.
    24. openai_api.py — the OpenAI-compatible /v1 surface (build_router() registers GET /v1/models, GET /v1/models/{id}, POST /v1/embeddings, POST /v1/chat/completions). Model turns only: parse_chat_request() validates the OpenAI schema (explicit 400s for unknown fields, n outside 1..8 or non-integer, logprobs, logit_bias, audio, non-text modalities, tool_choice: "required"), converts messages verbatim (assistant tool_calls, role: tool + tool_call_id→tool_name history, data-URI images) and ollama_payload() builds the /api/chat call; an n > 1 request emulates the fan-out as n sequential generations (indexed choices, summed usage, per-choice streaming indexes, capped at MAX_N = 8), and parallel_tool_calls: false is honored by truncating to the first returned call. parse_embeddings_request()/ embeddings_body() map POST /v1/embeddings onto /api/embed (string or string-array inputs, float/base64 encodings, dimensions forwarded, an embedding capability gate). Client tools pass through and never execute (the agent loop, tools registry and sessions are not reachable from this module). completion_body()/_stream_completion()/stream_chunk() shape the OpenAI response and SSE (role chunk, deltas, thinking as delta.reasoning_content, the tool calls as one indexed array chunk, finish reason, optional usage chunk, [DONE]); OpenAIApi keeps single-flight model-list/capability caches and builds one OllamaClient per request so a disconnecting client cancels only its own stream. The system extension ("auto" = built-in default, text = replace) is off unless asked. translate_error()/stream_backend_error() map upstream failures onto sanitized 404/502 envelopes with stable messages (raw backend detail goes to the --debug log).
    25. agent_api.py — the native agent endpoints (build_agent_api() constructs the one AgentApi; add_artifact_routes() registers the shared POST /v1/files and GET /v1/artifacts/* routes — kept even when serve_agent disables the agent surface — and add_agent_routes() registers POST /v1/agent/turns, GET /v1/agent/turns/{id} and .../events, POST .../cancel, POST /v1/agent/approvals/{id}, the /v1/sessions routes and the fit routes (POST /v1/agent/fit, POST /v1/agent/fits, GET /v1/agent/fits/{id}, POST /v1/agent/fits/{id}/cancel). parse_agent_turn() validates the turn body (new-session seed vs existing-session delta; settings.tools/max_rounds/approval/ system/parameters/cancel_on_disconnect). Each turn builds a headless Repl (its cancel_token and tool_ctx.cancel rewired to the turn's token) and runs AgentRuntime through TurnManager with the runtime's own tool execution, so the API approver and event sink apply to every round. The approver composes tools.policy_check (shared with the CLI), parks genuinely undecided calls in waiting_approval (PendingApproval + approval.required carrying its approval_id; the first decision wins, a timeout denies, cancellation resolves it as cancelled), and the serve tool policy is never auto. The events endpoint speaks the typed TurnEvent stream (id: <turn>:<seq>, ?after=/Last-Event-ID replay, stream.gap passthrough) and treats a disconnect as an unsubscribe unless cancel_on_disconnect; the status endpoint distinguishes 404 from 410 through TurnManager.expired(); session routes go through the store and refuse edits to a session with an active turn (409 session_busy, same as delete); serve_turn_timeout is a watchdog that cancels with reason timeout. The context warning/auto-compaction step runs headlessly at turn start through the runtime's on_started hook. Context control: PATCH/turn settings take num_ctx/gpu_layers (strictly validated; a placement change unloads the resident model) and a validated parameters merge (validate_settings_parameters: known Ollama options type/range checked, unknown names passed through bounded), settings.num_ctx: "max-gpu"|"max-cpu" estimates at turn start (estimate only) and rides the typed session.fit event plus result.fit, POST /v1/agent/fit serves the synchronous estimate with an optional apply, and POST /v1/agent/fits parks a probe job in fits.py. serve_fit gates off/estimate/probe; a fitting session is held by _fit_guard (409 session_busy with active_fit_id, checked alongside active turns by every session route and turn submit).
    26. cli.py — build_parser() (the full argparse surface, mirroring every ollama run flag), resolve_model/resolve_session (figuring out what model/session a given invocation means, including the -c/-r/ --session disambiguation in normalize_argv), ui_mode()/wants_tui() (which front end to start), build_serve_parser()/serve_main() (the ollamarun serve subcommand: upstream resolution, serve_settings() validation, banner, the combined OpenAI + agent router gated by serve_agent, and the ordered shutdown — refuse new work, cancel/join, drain handlers within serve_shutdown_timeout, then unload the tracked models unless --keep-loaded) and main() as the entry point (called by the top-level ollamarun script), which dispatches serve before the normal parser.

    Model housekeeping (unload-before-switch, unload-on-exit, embedding models always resident) is cross-cutting logic that lives in the REPL commands (cmd_model, cmd_load, both in repl.py) and main()'s exit path (cli.py), coordinated through /api/ps lookups in OllamaClient — not a separate module. The model picker those commands (and a model-less ollamarun run) open is ordered by the session's model_sort, seeded from --sort and updated whenever a sort is chosen at the prompt.

    Cross-module imports follow the numbering above (a module only imports from one earlier in the list, plus constants.py/helpers.py/events.py from anywhere) — keep new code on that side of the dependency graph rather than reaching "backwards" (e.g. don't import from repl.py inside renderer.py); use typing.TYPE_CHECKING for a backwards-pointing type hint only, the way renderer.py does for Session (defined later, in session.py).
